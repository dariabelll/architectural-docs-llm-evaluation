## C. Option model

- **RF-09** `Option` is a `Cloneable, Serializable` value object describing one command-line option: short name (`option`), long name (`longOption`), argument count (`argCount`), argument-name display (`argName`), `description`, `type`, `optionalArg`, `required`, `since`, `converter`, `deprecated`, `valueSeparator`, and a mutable `values` list. (`Option.java:41`, `Option.java:390-431`)
- **RF-10** `Option` argument-count constants: `UNINITIALIZED = -1` (not specified) and `UNLIMITED_VALUES = -2` (infinite). (`Option.java:362-365`)
- **RF-11** `Option` is constructed via a nested `Option.Builder` (implements `Supplier<Option>`); `Option.builder(String)` / `Option.builder()` are the entry points; the builder validates the option name through `OptionValidator.validate`. (`Option.java:55-353`, `Option.java:373-387`, `Option.java:259-262`)
- **RF-12** `Option` argument semantics: `hasArg()` = `argCount > 0 || UNLIMITED_VALUES`; `hasArgs()` = `argCount > 1 || UNLIMITED_VALUES`; `acceptsArg()` combines hasArg/hasArgs/hasOptionalArg with remaining capacity; `requiresArg()` returns false when `optionalArg`. (`Option.java:755-775`, `Option.java:507-509`, `Option.java:878-883`)
- **RF-13** `Option.processValue(String)` splits a raw token on `valueSeparator` into multiple stored values, stopping the split once `argCount-1` values are stored and adding the remainder as one token; it throws `IllegalStateException("NO_ARGS_ALLOWED")` when `argCount == UNINITIALIZED`. (`Option.java:844-871`)
- **RF-14** `Option.clone()` copies the `values` list (shallow-copy of the option, values list duplicated) so each parsed occurrence carries its own values. (`Option.java:556-565`)
- **RF-15** `Option.clearValues()` empties the stored values and is used to reset state between parses (CLI-71). (`Option.java:543-545`, `Parser.java:152-153`)
- **RF-16** `Option.getKey()` returns the short name if set, otherwise the long name; it is the identifier used for required-option tracking and group membership. (`Option.java:648-651`)
- **RF-17** `Option.getConverter()` falls back to `TypeHandler.getDefault().getConverter(type)` when no explicit converter was set; default `type` is `String.class`. (`Option.java:610-612`, `Option.java:425`, `Option.java:58`)
- **RF-18** `Option.getValues()` returns `null` (not an empty array) when there are no values; `getValuesList()` always returns the list. (`Option.java:728-730`, `Option.java:746-748`)

- **RF-19** `OptionValidator` (package-private, final) validates option names: first character must be a Java identifier part or `'?'`/`'@'` (`ADDITIONAL_OPTION_CHARS`); remaining characters must be a Java identifier part or `'-'` (`ADDITIONAL_LONG_CHARS`); empty names and illegal characters throw `IllegalArgumentException`. (`OptionValidator.java:23-145`)
- **RF-20** `OptionGroup` models a set of mutually exclusive options: it holds an ordered `Map<String,Option>`, a `selected` key and a `required` flag. (`OptionGroup.java:31-45`)
- **RF-21** `OptionGroup.setSelected(Option)` throws `AlreadySelectedException` when a *different* member is already selected; passing `null` resets the selection. `isSelected()` is `selected != null`. (`OptionGroup.java:134-147`, `OptionGroup.java:113-115`)

## D. Options registry

- **RF-22** `Options` is the "Main entry-point into the library" (its own javadoc) and is `Serializable`; it holds `shortOpts` and `longOpts` as `LinkedHashMap`s, `requiredOpts` as a `List<Object>` that may contain both option keys (`String`) and `OptionGroup`s, and `optionGroups` as a `Map<String,OptionGroup>` keyed by option key. (`Options.java:30-59`)
- **RF-23** `Options.addOption(Option)` registers the option in `longOpts` (if it has a long name) and `shortOpts` (always, under `getKey()`), and appends the key to `requiredOpts` when `isRequired()`. (`Options.java:74-89`)
- **RF-24** `Options.addOptionGroup(OptionGroup)` adds the group itself to `requiredOpts` when required, then for each member option forces `setRequired(false)`, removes it from `requiredOpts`, registers it via `addOption`, and maps the option key to the group. An option inside a group can therefore never itself be required. (`Options.java:150-165`)
- **RF-25** `Options.getOption(String)` / `hasOption` / `hasShortOption` / `hasLongOption` first normalize the name through `Util.stripLeadingHyphens` (strips up to two leading hyphens), then look up `shortOpts` first and fall back to `longOpts`. (`Options.java:243-247`, `Options.java:298-323`, `Util.java:75-86`)
- **RF-26** `Options.getMatchingOptions(String)` implements long-option **partial matching**: exact long-name match returns a singleton; otherwise all long names starting with the cleaned prefix are returned (empty/null input yields an empty list). (`Options.java:220-232`)
- **RF-27** `Options.getRequiredOptions()` returns an unmodifiable list containing both option keys and `OptionGroup` instances; `getOptionGroups()` de-duplicates group values through a `HashSet`; `getOptions()` returns an unmodifiable collection backed by `helpOptions()`. (`Options.java:264-289`, `Options.java:330-332`)
- **RF-28** `Options.addOptions(Options)` merges another `Options`, throwing `IllegalArgumentException("Duplicate key: ...")` on key collision, and also re-adds the source's option groups. (`Options.java:175-184`)
- **RF-29** `Options` is not thread-safe by design and offers a fluent API returning `this`. (`Options.java:74-211`)

## E. Parsers

- **RF-30** `CommandLineParser` is the parsing SPI: `CommandLine parse(Options, String[])` and `CommandLine parse(Options, String[], boolean stopAtNonOption)`. Implementations: `DefaultParser` (direct) and the abstract `Parser` hierarchy. (`CommandLineParser.java:24-50`)
- **RF-31** `DefaultParser implements CommandLineParser` directly (since 1.3) — a **single-pass** parser. `Parser` is `@Deprecated` and implements a **two-pass** algorithm (abstract `flatten` followed by token processing). (`DefaultParser.java:35`, `Parser.java:32-35`, `Parser.java:74`)
- **RF-32** `DefaultParser` configurable state: `allowPartialMatching` (default `true`), `stripLeadingAndTrailingQuotes` (tri-state `Boolean`, default `null` = historic behaviour) and a `deprecatedHandler` `Consumer<Option>`; exposed through `DefaultParser.builder()` / `Builder.get()`. (`DefaultParser.java:47-152`, `DefaultParser.java:230-243`, `DefaultParser.java:262-266`)
- **RF-33** `DefaultParser.NonOptionAction` enum (since 1.10.0) with values `IGNORE`, `SKIP`, `STOP` (equivalent to `stopAtNonOption=true`) and `THROW` (equivalent to `stopAtNonOption=false`); the boolean overloads delegate to `STOP`/`THROW`. (`DefaultParser.java:159-177`, `DefaultParser.java:810-813`)
- **RF-34** `DefaultParser.parse(Options, Properties, NonOptionAction, String...)` is the canonical entry point: it stores the options/action, resets `skipParsing`/`currentOption`, snapshots `options.getRequiredOptions()` into `expectedOpts`, clears the `selected` member of every option group, builds the `CommandLine` with the deprecated handler, then calls `handleToken` for each argument, then `checkRequiredArgs`, `handleProperties`, `checkRequiredOptions`. (`DefaultParser.java:739-762`)
- **RF-35** `DefaultParser.handleToken` dispatch order: (1) `skipParsing` → add token as a plain argument; (2) token `"--"` → set `skipParsing = true`; (3) `currentOption != null && currentOption.acceptsArg() && isArgument(token)` → feed token as an option value; (4) token starts with `"--"` → `handleLongOption`; (5) token starts with `"-"` and is not exactly `"-"` → `handleShortAndLongOption`; (6) otherwise → `handleUnknownToken`. (`DefaultParser.java:600-620`)
- **RF-36** `handleShortAndLongOption` recognizes the token forms `-S`, `-S=V`, `-L`/`-l`, `-L=V`/`-l=V`, `-LV`, `-S1S2` (concatenated shorts via `handleConcatenatedOptions`), Java-property style `-Dkey` / `-Dkey=value` via `isJavaProperty`, and long-prefix style `-Xmx512m` via `getLongPrefix`. (`DefaultParser.java:533-592`, `DefaultParser.java:345-357`, `DefaultParser.java:657-661`)
- **RF-37** `getLongPrefix(token)` scans prefixes from longest to shortest (from `length-2` down to index 2) for a registered long option name, enabling JVM-style attached values such as `-Xmx512m`. (`DefaultParser.java:345-357`)
- **RF-38** When partial matching is enabled and more than one long option matches while the token is not an exact long name, parsing fails with `AmbiguousOptionException`. (`DefaultParser.java:442-443`, `DefaultParser.java:470-471`)
- **RF-39** `handleUnknownToken` throws `UnrecognizedOptionException` for dash-prefixed tokens only when `nonOptionAction == THROW`; otherwise the token becomes an argument, and `nonOptionAction == STOP` sets `skipParsing` so all remaining tokens are collected as arguments. (`DefaultParser.java:630-641`)
- **RF-40** `isArgument(token)` = `!isOption(token) || isNegativeNumber(token)`; `isNegativeNumber` succeeds when `Double.parseDouble` accepts the token, so negative numbers can be option values. `isOption = isLongOption || isShortOption`. (`DefaultParser.java:648-650`, `DefaultParser.java:690-697`, `DefaultParser.java:704-706`)
- **RF-41** Quote stripping is tri-state: `stripLeadingAndTrailingQuotesDefaultOn` strips when the flag is `null` or `true` (used for space-separated values), `stripLeadingAndTrailingQuotesDefaultOff` strips only when the flag is explicitly `true` (used for inline `-o=value`/`-Svalue` forms). Both delegate to `Util.stripLeadingAndTrailingQuotes`, which removes only balanced outer double quotes with no interior quote. (`DefaultParser.java:821-839`, `Util.java:58-67`)
- **RF-42** Every option occurrence handled by the parser is `clone()`d before being stored on the `CommandLine`, and the clone becomes `currentOption` when it takes an argument. (`DefaultParser.java:478-485`)
- **RF-43** `DefaultParser.checkRequiredArgs()` throws `MissingArgumentException` when `currentOption.requiresArg()`, except for a Java-property option (`-Dflag`) that already received exactly one value. (`DefaultParser.java:319-326`)
- **RF-44** `DefaultParser.updateRequiredOptions(Option)` removes the option key from `expectedOpts` when required, and, if the option belongs to a group, removes the group when required and marks the option as the group's `selected` member (which may throw `AlreadySelectedException`). (`DefaultParser.java:846-858`)
- **RF-45** `DefaultParser.handleProperties(Properties)` applies default values from a `Properties` object: an unknown key raises `UnrecognizedOptionException("Default option wasn't defined")`; options already present on the command line and options in an already-selected group are skipped; a value-taking option is filled only when it has no values yet; a flag option is enabled only when the property value is `yes`, `true` or `1` (case-insensitive), otherwise it is skipped. (`DefaultParser.java:492-520`)
- **RF-46** The deprecated `Parser` base class performs a two-pass parse: `flatten(...)` produces atomic tokens, then the shared loop handles `"--"`, `"-"`, option tokens and arguments; `stopAtNonOption` turns the rest of the token stream into arguments, and only a single `"--"` is added. (`Parser.java:150-207`)
- **RF-47** `Parser.parse` resets state before parsing: it clears values of all help options (`options.helpOptions().forEach(Option::clearValues)`), clears the `selected` member of all groups, and snapshots required options in `setOptions`. (`Parser.java:152-160`, `Parser.java:311-314`)
- **RF-48** `BasicParser`, `GnuParser` and `PosixParser` are `@Deprecated` `Parser` subclasses, each supplying only `flatten`: `BasicParser` echoes the arguments unchanged; `GnuParser` splits `--opt=value` and `-Dproperty=value` forms; `PosixParser` performs partial long matching (throwing `AmbiguousOptionException`) and bursting of concatenated short options. (`BasicParser.java:26-56`, `GnuParser.java:30-98`, `PosixParser.java:135-235`)
- **RF-49** `Parser.processOption` throws `UnrecognizedOptionException` for unknown tokens, clones the matched `Option`, updates required options/groups, calls `processArgs` when the option takes an argument, and throws `MissingArgumentException` if the option ends with no values and no optional arg. (`Parser.java:247-263`, `Parser.java:217-237`)

## F. CommandLine result object

- **RF-50** `CommandLine` is the parse result: it holds `List<String> args` (a `LinkedList` of leftover/non-option tokens) and `List<Option> options` (an `ArrayList` of processed options, each a clone carrying its own values), plus a transient `deprecatedHandler`; it is `Serializable` and built through `CommandLine.builder()`. (`CommandLine.java:41`, `CommandLine.java:150-178`, `CommandLine.java:48-135`)
- **RF-51** `CommandLine.resolveOption(String)` resolves a user-supplied name by stripping leading hyphens and searching the processed options for a matching `getOpt()` or `getLongOpt()`. (`CommandLine.java:1035-1043`)
- **RF-52** Value lookup API: `hasOption` (char/String/`Option`/`OptionGroup`), `getOptionValue(s)` (single/all values, with default-value and `Supplier` variants), `getOptionProperties` (converts value pairs into `Properties`, odd trailing value → `"true"`), `getOptionCount` (since 1.11.0), `iterator()`, `getArgs()`, `getArgList()`. (`CommandLine.java:963-1013`, `CommandLine.java:221-232`, `CommandLine.java:241-265`, `CommandLine.java:307-335`, `CommandLine.java:1023-1027`)
- **RF-53** Typed access: `getParsedOptionValue(...)` applies `Option.getConverter()` to the first value and wraps failures via `ParseException.wrap`; `getParsedOptionValues(...)` (since 1.10.0) converts every value and builds the result array with `java.lang.reflect.Array.newInstance(clazz, length)`. (`CommandLine.java:610-624`, `CommandLine.java:801-820`)
- **RF-54** Deprecation warnings are emitted lazily, when the application queries `hasOption`/`getOptionValues` for a deprecated option, by invoking the `deprecatedHandler`; the default handler prints `Option.toDeprecatedString()` to `System.out`. (`CommandLine.java:933-937`, `CommandLine.java:976-979`, `CommandLine.java:508-510`, `CommandLine.java:53`)
- **RF-55** `getOptionProperties` is implemented by walking values two at a time (`processPropertiesFromValues`); `getOptionValue(OptionGroup)` returns the value of the group's currently selected option. (`CommandLine.java:1023-1027`, `CommandLine.java:422-424`, `CommandLine.java:524-529`)

## G. Type conversion

- **RF-56** `Converter<T,E>` is a `@FunctionalInterface` (`T apply(String) throws E`) with predefined constants `DEFAULT` (identity), `CLASS` (lazy `Class.forName`), `FILE`, `PATH`, `NUMBER` (Double if the string contains '.', otherwise Long), `OBJECT` (class name → no-arg constructor), `URL`, and `DATE` (strict `SimpleDateFormat` with pattern `EEE MMM dd HH:mm:ss zzz yyyy`, lenient=false, whole-string consumption required, `Locale.ENGLISH` fallback). (`Converter.java:34-115`)
- **RF-57** `TypeHandler` holds a `Map<Class<?>, Converter<?, ? extends Throwable>>` and exposes a process-wide singleton via `TypeHandler.getDefault()`; the default map registers Object, Class, Date, File, Path, Number, URL, FileInputStream, Long, Integer, Short, Byte, Character (with `\uXXXX` support), Double, Float, BigInteger, BigDecimal. Unknown classes fall back to `Converter.DEFAULT`. (`TypeHandler.java:45`, `TypeHandler.java:203-205`, `TypeHandler.java:220-251`, `TypeHandler.java:290-292`)
- **RF-58** `TypeHandler` static helpers (`createValue`, `createClass`, `createFile`, `createURL`, `createNumber`, `createObject`, `createDate`, `openFile`) delegate to the converter map and wrap failures with `ParseException.wrap`; most are `@Deprecated`. `createFiles`/`createDate` are not implemented (unsupported operations). (`TypeHandler.java:57-218`, `TypeHandler.java:106-111`)
- **RF-59** `DeprecatedAttributes` is an immutable value object (`description`, `since`, `forRemoval`) with its own `Builder`; `Option.isDeprecated()` is `deprecated != null`. (`DeprecatedAttributes.java:34`, `DeprecatedAttributes.java:39`, `DeprecatedAttributes.java:128-134`, `Option.java:816-818`)

## H. Legacy option builders

- **RF-60** `OptionBuilder` is a `@Deprecated`, **static-state** (non-thread-safe, JIRA CLI-209) builder: all configuration is held in static fields and a singleton `INSTANCE`, with `reset()` restoring defaults. (`OptionBuilder.java:31-64`)
- **RF-61** `PatternOptionBuilder.parsePattern(String)` builds an `Options` from a compact pattern string where a value code after a letter gives the argument type (`@`=Object, `:`=String, `%`=Number, `+`=Class, `#`=Date, `<`=FileInputStream, `>`=File, `*`=File[], `/`=URL) and `!` marks the preceding option required; each option gets a `Converter` from a fresh `TypeHandler` default map (`File[]` deliberately maps to an unsupported converter). ## I. Exception hierarchy

- **RF-62** `ParseException extends Exception` (checked) and provides `ParseException.wrap(Throwable)`, which returns the argument if it is already a `ParseException`, rethrows `UnsupportedOperationException` untouched, and otherwise wraps. (`ParseException.java:23`, `ParseException.java:44-52`)
- **RF-63** Subtypes of `ParseException`: `MissingOptionException` (carries the list of missing options, which mixes option keys and groups), `MissingArgumentException` (carries the `Option`), `UnrecognizedOptionException` (carries the offending option name), `AlreadySelectedException` (carries the `OptionGroup` and the rejected `Option`). (`MissingOptionException.java:25-51`, `MissingArgumentException.java:23-39`, `UnrecognizedOptionException.java:23-49`, `AlreadySelectedException.java:23-43`)
- **RF-64** `AmbiguousOptionException extends UnrecognizedOptionException` and carries the option name plus the collection of partially matching long names. (`AmbiguousOptionException.java:28-68`)

## J. Help subsystem (`org.apache.commons.cli.help`, since 1.10.0)

- **RF-65** `HelpAppendable` is the output SPI: it extends `java.lang.Appendable` and adds semantic operations `appendHeader(level, text)`, `appendList(ordered, list)`, `appendParagraph`, `appendTable(TableDefinition)`, `appendTitle`, plus default helpers `appendFormat` and `appendParagraphFormat`. The abstraction is format-neutral so that text, XHTML, Markdown or APT renderers can be plugged in. (`HelpAppendable.java:24-120`, `help/package-info.java:19-30`)
- **RF-66** `FilterHelpAppendable` is an abstract `HelpAppendable` that delegates the three `Appendable` primitives to a protected underlying `Appendable output`; it is the designated base class for output filters. (`FilterHelpAppendable.java:38-72`)
- **RF-67** `TextHelpAppendable extends FilterHelpAppendable` and is the plain-text renderer: it wraps text (`printWrapped`, `indexOfWrap` at a static `DEFAULT_WIDTH = 74`, `DEFAULT_LEFT_PAD = 1`, `DEFAULT_INDENT = 3`, `DEFAULT_LIST_INDENT = 7`), renders headers/titles with fill characters (`=`, `%`, `+`, `_`, `#`), and renders tables after rescaling columns through `adjustTableFormat` (scalable columns shrink to fit the page width). `systemOut()` builds one over `System.out`. (`TextHelpAppendable.java:35-49`, `TextHelpAppendable.java:75-132`, `TextHelpAppendable.java:152-265`)
- **RF-68** `TableDefinition` is an immutable description of a table (`caption`, per-column `TextStyle`s, `headers`, `rows`) with a static `from(...)` factory. (`TableDefinition.java:36-101`)
- **RF-69** `TextStyle` is the immutable column/paragraph style: `alignment` (LEFT/CENTER/RIGHT), `indent`, `leftPad`, `maxWidth`, `minWidth`, `scalable` flag and a `pad(...)` operation; `TextStyle.DEFAULT` and a builder are provided. (`TextStyle.java:28`, `TextStyle.java:236-392`)
- **RF-70** `OptionFormatter` is an immutable per-`Option` view with a `Builder` holding all presentation defaults: `DEFAULT_OPT_PREFIX="-"`, `DEFAULT_LONG_OPT_PREFIX="--"`, `DEFAULT_OPT_SEPARATOR=", "`, `DEFAULT_OPT_ARG_SEPARATOR=" "`, `DEFAULT_ARG_NAME="arg"`, optional delimiters `"["`/`"]"`, arg-name delimiters `"<"`/`">"`, plus deprecated-format functions `NO_DEPRECATED_FORMAT`, `SIMPLE_DEPRECATED_FORMAT`, `COMPLEX_DEPRECATED_FORMAT`. (`OptionFormatter.java:32-37`, `OptionFormatter.java:228-294`)
- **RF-71** `OptionFormatter` exposes `getOpt()`, `getLongOpt()`, `getBothOpt()` (short and long joined with the separator), `getArgName()` (delimited, defaulted to `arg`, empty when the option takes no argument), `getDescription()`, `getSince()`, `isRequired()`, `toOptional(text)` and `toSyntaxOption()`. (`OptionFormatter.java:384-480`)
- **RF-72** `AbstractHelpFormatter` (since 1.10.0) is the framework that binds a `HelpAppendable` + an `OptionFormatter.Builder` + an option `Comparator` + an option-group separator (`" | "`) + a syntax prefix (`"usage: "`) into standardized help output; subclasses only supply `getTableDefinition(Iterable<Option>)`. Its `Builder<B extends Builder<B,T>, T extends AbstractHelpFormatter>` is a self-typed generic builder whose defaults are a `TextHelpAppendable` on `System.out`, the default `OptionFormatter.Builder`, `DEFAULT_COMPARATOR` (case-insensitive compare on `Option.getKey()`) and `" | "`. (`AbstractHelpFormatter.java:39-165`, `AbstractHelpFormatter.java:167-213`)
- **RF-73** `AbstractHelpFormatter.printHelp(cmdLineSyntax, header, options, footer, autoUsage)` emits: the usage paragraph (with the auto-generated syntax line only when `autoUsage`), the header paragraph, the option table (`getTableDefinition(options.getOptions())`) and the footer paragraph; an empty `cmdLineSyntax` raises `IllegalArgumentException`. (`AbstractHelpFormatter.java:296-344`)
- **RF-74** `AbstractHelpFormatter.toSyntaxOptions(...)` renders the usage syntax: options belonging to a group are emitted once as a group, group members are joined by `optionGroupSeparator` and the whole group is wrapped in optional delimiters when the group is not required; other options are wrapped in optional delimiters when not required. (`AbstractHelpFormatter.java:431-508`)
- **RF-75** `help.HelpFormatter extends AbstractHelpFormatter` is the default concrete formatter (`HelpFormatter.builder().get()`): a 3-column table `Options | Since | Description` with `showSince` defaulting to `true`, `DEFAULT_WIDTH = 74`, `DEFAULT_LEFT_PAD = 1`, `DEFAULT_COLUMN_SPACING = 5`; the first column joins `getBothOpt()` with a space and the argument name. (`HelpFormatter.java:62-62`, `HelpFormatter.java:72-102`, `HelpFormatter.java:104-132`, `HelpFormatter.java:163-208`)
- **RF-76** The help subsystem is pluggable end-to-end: `AbstractHelpFormatter.Builder.setHelpAppendable(...)` selects the output format and `setOptionFormatBuilder(...)` selects option presentation, so alternative renderers can be supplied without touching the model or the parsers. (`AbstractHelpFormatter.java:132-151`)

## L. End-to-end flows

- **RF-80** **Definition flow:** application creates `Option`s (builder or constructor), registers them in an `Options` registry (possibly via `OptionGroup`s), and passes the registry to a parser. (`Option.java:373-499`, `Options.java:74-165`, `CommandLineParser.java:34`)
- **RF-81** **Modern parse flow:** `DefaultParser.parse(options, properties, action, args)` → per-token `handleToken` → `handleOption` (clone + required/group bookkeeping + `cmd.addOption`) → `Option.processValue` for attached/separate values → `checkRequiredArgs` → `handleProperties` → `checkRequiredOptions` → returns the populated `CommandLine`. (`DefaultParser.java:739-762`, `DefaultParser.java:478-485`, `Option.java:844-871`)
- **RF-82** **Legacy parse flow:** `Parser.parse` → `flatten` (subclass-specific token normalization) → shared token loop with `processOption`/`processArgs` → `processProperties` → `checkRequiredOptions`. (`Parser.java:150-207`)
- **RF-83** **Help flow:** `HelpFormatter.builder().get()` → `printHelp(cmdLineSyntax, header, options, footer, autoUsage)` → `toSyntaxOptions(options)` for the usage line and `getTableDefinition(options.getOptions())` for the table → `HelpAppendable.appendParagraphFormat` / `appendTable`, which in `TextHelpAppendable` wraps and column-rescales the content before writing to the underlying `Appendable`. (`AbstractHelpFormatter.java:327-344`, `HelpFormatter.java:163-208`, `TextHelpAppendable.java:243-254`)
- **RF-84** **Typed value flow:** raw token → `Option.processValue` stores `String`s → `CommandLine.getParsedOptionValue` applies `Option.getConverter()` (explicit converter, otherwise `TypeHandler.getDefault().getConverter(type)`) → typed object, with `ParseException.wrap` on failure. (`Option.java:844-871`, `CommandLine.java:610-624`, `Option.java:610-612`)
- **RF-85** **Error flow:** every parse failure surfaces as a `ParseException` subtype thrown from the parser (`MissingOptionException`, `MissingArgumentException`, `UnrecognizedOptionException`/`AmbiguousOptionException`, `AlreadySelectedException`); the only checked exception declared by `CommandLineParser` is `ParseException`. (`CommandLineParser.java:32`, `ParseException.java:23`, `MissingOptionException.java:25`, `MissingArgumentException.java:23`, `UnrecognizedOptionException.java:23`, `AmbiguousOptionException.java:28`, `AlreadySelectedException.java:23`)
